### Session pickup

**接续点由你负责。读之前留下的 trail（决策和操作的记录），不要把它重做一遍。**

1. 找到之前的 trail。它可能是当前工作区 `agent-transcripts/` 目录下的本地对话记录（系统提示词里写了路径。不要用 glob 横扫 `~/.cursor/projects/*/`，那样会越过工作区的边界，读到无关项目里的私人聊天），可能是一个 cloud-agent URL，也可能是一个已经推送的分支。先读元数据概览和最后几条消息，再往前翻，找出做决定的节点。长的对话记录交给子代理解析，主对话里保留缩减后的时间线（**principle-guard-the-context-window** skill）。
2. 还原当时的工作状态：分支和 worktree，已经落地的内容（`git log`，以及相对 base 的 `git diff`），还没完成的待办，已经做出的决定。之前的 trail 是权威输入。克制住重新推导一遍的倾向。
3. 对比已完成和待完成的部分。拿已经交付的内容和原计划对照，说出接续点。不要重跑之前的复现，也不要重做已经完成的工作。想「从头验证一遍」，就说明你把 trail 当成了不可信的东西，而它其实是权威的。
4. 把剩下的工作交给对应的 playbook，并选定 verdict（判定结论）：继续执行，交付一份已经完成的建议，认可或推翻之前的结论，或者给失败的那次运行做复盘。这个 playbook 到这里结束。后面的事归转过去的那个 playbook。
5. 在真实产物上，对照原始目标验证接手过来的各项说法（**principle-prove-it-works** skill）。之前的自我报告说通过了，不算证明。

**回复：** 之前的 agent 停在哪里、哪些是你接过来的、哪些是你重做的（最好什么都没重做）、接续点，以及结果。
