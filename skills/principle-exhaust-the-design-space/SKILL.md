# 穷举设计空间

当 novel interaction 或架构决策没有既定先例时，在实现前探索若干具体替代方案。做错的东西比探索三个选项成本更高。

**规则。** 当正确答案不明显时，构建 2-3 个竞争原型或草图。并排比较。然后再承诺。Design it twice 是本规则的另一种说法。第一种形状的第二个变体不算。

**适用场景：**
- Novel UI 交互（代码库中无 prior art）
- 有多种可行方案的架构选择
- 用户体验取决于感觉而非逻辑的产品设计决策

**不适用：**
- 模式已确立的机械实现
- 目标状态明确的 bug 修复或重构
- 约束决定只有一种可行方案的变更
