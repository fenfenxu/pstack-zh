# 懒惰协议

用最少的代码和复杂度拿到最大结果。

- **优先删除。** 被要求重构或改进时，先找能删的，再考虑加东西。
- **保持扁平的调用层次。** 避免深调用链。能藏住大量工作的丰富接口，不等于深调用链。若回答一个问题需要追超过 3 个文件或层级，就压平。
- **合并决策。** 不要在多处重复同一选择。放在单一事实来源，再把结果当简单标志传递。
- **最小化 diff。** 只做能解决问题的最小变更。更少行数胜过「优雅」样板。
- **质疑穿线。** 若任务要把新信号一路穿过类型、schema、管道或类似层，先停下来找更直接的路径。
- **处理小泄漏。** 在扩散前移除细小的透传、表示泄漏和重复选择。小泄漏会累积成长期协调成本。

**检验：** 若人类开发者会觉得这份代码维护起来筋疲力尽，就是坏方案。
