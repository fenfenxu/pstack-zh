# Slack 对话

## 这个来源里有什么

- 问题与决策的实时讨论
- 事故频道中的火线决策
- 权衡辩论的设计讨论串
- 资深工程师回答但未写入文档的问题
- 合并后解释为何重新审议的讨论
- 私信（通常不可搜，范围 相应调整）

Slack 常是*真实*决策发生处，尤其小变更不值得写文档时。也是最易逝的来源：讨论串会删、频道会归档、搜索质量随时间下降。

## 怎么搜

Slack MCP 工具因环境而异。先查可用 Slack MCP 并查看工具 schema。可能需要 `mcp_auth`。认证失败则停止并报告缺口。

1. **按作者限定。** PR 作者 在 PR 合并日期前后的消息。大幅收窄范围，常命中关键内容。
2. **功能名与关键符号关键词搜索。** 含拼写变体与口语说法。
3. **PR URL 搜索。** Slack 常在 评审 或讨论时链 PR。搜 PR URL（或 `/pull/<number>`）。
4. **错误字符串搜索。** 若代码处理特定错误，搜该字符串。事故讨论串常浮现。
5. **频道限定搜索。** 收窄到可能频道：
   - `#eng-*`。工程讨论
   - `#proj-*`。项目频道
   - `#incident-*` / `#sev-*`。事故频道
   - 负责团队的团队频道
   - 设计评审频道
6. **讨论串遍历。** 找到相关消息后拉整串。决策常在回复里。

## 这里怎样算好证据

- 明确辩论权衡的讨论串（「本打算用 A，但 B 更好因为……」）
- 事故频道描述该代码所防 bug 的消息
- 评审者提问与作者或负责人的权威回答
- 引用做过决策的会议
- 产品经理或面向客户工程师解释客户诉求的消息

## 常见陷阱

- **频道考古限制。** 很旧消息可能因 保留策略消失。若某日期前搜不到，注明 保留策略截止点。
- **未搜到的私信。** 许多决策在不可搜私信里。会漏。这是已知限制。
- **玩笑当「决策」。** Slack 很 随意。「哈哈就这么干」不是决策，即使出现在提交之前。找经过考虑的讨论。
- **单条消息上下文 坍塌。** 无讨论串时单条常误读。始终拉整串。
- **认证失败。** MCP 未认证则停止。不要编造发现。报告 Slack 不可搜。

## 要返回什么

每个相关讨论串：
- 频道名
- 永久链接或讨论串 ID
- 参与者
- 讨论日期范围
- 关键引用（逐字）及 归属
- 上下文：属于哪条讨论串/事故/讨论
