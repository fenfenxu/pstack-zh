# Notion 文档

## 这个来源里有什么

- PRD（产品需求文档）
- 技术规格与 RFC
- 架构决策记录（ADR）
- 设计评审会议纪要
- 带领域上下文的团队页面
- 事故事后复盘
- 可能解释防御性代码的运行手册
- 设定优先级的战略文档

Notion 常是「为什么」在成为代码之前的长文栖身之处。重要功能通常有文档。

## 怎么搜

使用 Notion MCP。

1. **用 `notion-search` 关键词搜索。** 尝试：
   - 功能名
   - 目标代码的关键符号/类名
   - 作者 账号（设计文档常在代码落地前由作者写）
   - 错误字符串或用户可见术语
   - 若知代码发布时间，可加时间范围
2. **用 `notion-fetch` 拉取候选页。** 读全文，不要只看预览。理由常在文档中部。
3. **跟随反向链接与子页。** 设计文档常有「曾考虑的替代方案」、附录或实现说明子页。
4. **查相关数据库。** `notion-query-data-sources` 与 `notion-query-meeting-notes` 可 浮现讨论该决策的会议纪要。
5. **搜作者个人空间。** 若 PR 作者有个人笔记本（部分公司常见），可能有先于代码的探索性思考。

## 这里怎样算好证据

- PRD 的「问题陈述」或「动机」与目标代码目的匹配
- 「曾考虑的替代方案」或「拒绝的方案」节
- 事后复盘将目标代码点名为某事故的修复
- 会议纪要记录「我们决定 X 因为 Y」，且作者/日期与 PR 一致
- 非敷衍填写的 ADR 模板（状态、上下文、决策、后果）

## 常见陷阱

- **过时文档。** 规格常在实现前写且不更新。文档可能是已变计划。与实际 PR 交叉验证。
- **文档与实现漂移。** 规格写「我们将做 X」但代码做 Y。标出分歧。合成器会呈现矛盾。
- **模板套话。** 有些组织要求填「Why」但内容空洞。找具体性。
- **未链接文档。** 最相关文档可能无处链接。广泛关键词搜索有帮助。
- **多份草稿。** 同一主题多文档时，找定稿或最近更新版。看日期。
- **访问受限页。** 无法访问则记为缺口。

## 要返回什么

每份相关文档：
- 标题与 URL
- 作者与最后更新日期
- 动机文本（逐字引用）及页/节位置
- 相关链接页（供合成器引用）
- 文档是定稿还是草稿
