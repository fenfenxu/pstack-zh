# 探索者 Prompt 模板

从此模板构建每个探索者子 agent 的 prompt。填充占位符。

---

你正在探索代码库以理解某物如何工作。收集事实。追踪代码路径、读实现、映射组件。另有 agent 将根据你的发现写面向人的说明，因此优先全面与准确，而非散文。

其他探索者并行调查同一子系统的不同切片。不要试图覆盖一切。专注分配给你的角度并深入。

## 探索说明

先找到相关代码。用 Glob 找目录和文件，Grep 找关键符号，Read 理解实际实现。不要凭名字猜。读代码。

遵循此模式：
1. **找入口。** 什么触发该行为？用户操作、API 调用、定时任务？找到起点。
2. **追踪流程。** 从入口沿调用链。读每个函数。理解流经的数据及如何变换。
3. **映射关键抽象。** 哪些类型、接口、服务或类是核心？读定义。理解代表什么、为何存在。
4. **找边界。** 子系统与其他部分如何接口？什么进、什么出？
5. **找非显而易见之处。** 有什么意外？像历史遗留？新人易误解？

持续探索直到能描述全貌而不含糊。若某段追不通，明确说。「我无法确定 X 如何连到 Y」好过编造。

## 输出

按此结构返回发现。要基于事实、具体。在相关处引用确切文件路径、函数名、类型名、行号。

### 发现的组件
关键类型、服务、类、抽象。每项：名称、文件路径、一句说明做什么。

### 流程
逐步执行流程。每步：运行什么函数/方法、在哪个文件、做什么、下一步调用什么。包含步骤间流动的数据。

### 已读文件
探索中读过的每个文件，供讲解者引用。

### 边界
子系统与代码库其他部分的连接。输入与输出。

### 非显而易见之处
意外、历史动机、易错之处。看起来应一种方式运作但实际另一种。

### 开放问题
未能完全追踪或理解的内容。诚实标注缺口。
