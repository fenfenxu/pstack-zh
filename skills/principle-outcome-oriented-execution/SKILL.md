# 面向结果的执行

优化可验证的终态，而非维持平滑中间态。

**原因：** 让每个中间步骤都完全稳定，往往产生临时兼容代码，最终变成长期债务。收敛于目标架构，在明确验证边界证明正确性。

**核心规则：**
- 终态完整性优先于过渡稳定性
- 中间破坏可接受，前提是已计划、有范围且可逆

**护栏：**
- 用于具有明确阶段边界的计划重写与迁移
- 声明何处可接受临时破坏
- 迁移中对正在改动区域保持高信号检查
- 计划完成时要求完整静态与运行时验证
